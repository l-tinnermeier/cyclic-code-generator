# Cyclic Code Simulator

A Java Swing simulator for a (15,11) cyclic code using **g(x) = 1 + x³ + x⁴**. It encodes an 11-bit message, lets you introduce a single-bit error, and shows how the decoder finds and corrects it.

The circuits show the bits stored in each register, the values waiting for the next clock, and the calculations at each XOR gate.

## Running the project

The project uses Java's built-in Swing and AWT libraries. There are no external dependencies or build tools to install.

### Eclipse

1. Install a JDK and Eclipse with Java support. The project has been compiled with JDK 24.
2. Clone this repository.
3. In Eclipse, choose **File → Import → General → Existing Projects into Workspace** and select the cloned folder.
4. If Eclipse reports a missing JRE, select your installed JDK under the project's **Java Build Path → Libraries**.
5. Open `src/MainDisplay.java` and run it as a **Java Application**.

### Terminal

From the repository's root directory:

```sh
mkdir -p bin
javac -encoding UTF-8 -d bin src/*.java
java -cp bin MainDisplay
```

The application needs a graphical desktop to display its window.

## Using the simulator

### Enter a message

Enter exactly **11 binary digits**, including any leading zeros, then click **ENCODE**. The boxes preview the message you entered.

### Encode

Each clock is split into two actions:

- **Follow signals** calculates the XOR outputs and the next register values. The stored bits do not change yet.
- **Clock registers** loads all four next values together and advances the clock count.

Inside each register, **holds** shows its stored bit. Underneath, **next** shows the bit it will load on the next clock edge. **Auto play** runs these same actions automatically.

After 11 clocks, the encoder displays the four check bits and the complete 15-bit codeword. Click **Transmission / error →** to continue.

### Introduce an error

Click one of the 15 bit buttons to flip it. The changed bit is marked in red.

- Clicking the same bit again removes the error.
- Clicking a different bit restores the previous bit and flips the new one.
- **Reset** restores the original codeword.

Leave the bits unchanged to try transmission without an error. Click **DECODE** to send the displayed bits to the decoder.

### Decode and correct

Use **Follow signals**, **Clock registers**, or **Auto play** to process the 15 received bits.

When decoding finishes, the screen shows the syndrome, detected error position, corrected codeword, and recovered 11-bit message. It also compares the recovered message with the original and checks that the corrected word has a zero syndrome.

## Bit order and circuit logic

Both circuits read **right to left (LSB first)**. Bit position **0** is the rightmost bit; position **14** is the leftmost bit of a codeword. Keep leading zeros when entering or displaying messages.

The displayed codeword is arranged as:

```text
[4 check bits: R0 R1 R2 R3] [11 original message bits]
```

This means the decoder reads the message bits first, followed by the check bits from right to left. The recovered message is the rightmost 11 bits of the corrected codeword.

All registers start at zero. The updates below use the **old** register values; all four results are stored together at the clock edge. `^` means XOR: its result is 1 when its inputs differ.

| Signal | Encoder | Decoder |
| --- | --- | --- |
| Feedback | `input ^ R3` | `R3` |
| Next R0 | `feedback` | `input ^ feedback` |
| Next R1 | `R0` | `R0` |
| Next R2 | `R1` | `R1` |
| Next R3 | `R2 ^ feedback` | `R2 ^ feedback` |

The degree-four polynomial requires four registers. Its nonzero terms determine the feedback connections shown in the circuits.

After 15 decoding clocks, the syndrome is displayed as **R3 R2 R1 R0**. Internally it is `R0 | (R1 << 1) | (R2 << 2) | (R3 << 3)`. This display order differs from the encoder's check-bit order above.

The syndrome table is generated by passing each of the 15 possible single-bit error patterns through the decoder. A nonzero syndrome identifies the corresponding bit to flip. Since arrays are stored left to right, error position `p` maps to array index `14 - p`.

The simulator supports **no error or one bit error**. Multiple errors are outside its correction capability; a zero syndrome alone does not prove that an arbitrary received word is unchanged.

## Testing

On the error screen, click **Test all errors**. The table checks the current message with no error and with each of the 15 possible single-bit errors. Each row checks the detected position, corrected word, recovered message, and zero syndrome after correction. The expected result is **16/16 passed**.

For a quick manual example:

```text
Message:            10010101110
Encoded word:       110010010101110
Flip bit 0:         110010010101111
Syndrome R3..R0:     1100
Corrected word:     110010010101110
Recovered message: 10010101110
```
